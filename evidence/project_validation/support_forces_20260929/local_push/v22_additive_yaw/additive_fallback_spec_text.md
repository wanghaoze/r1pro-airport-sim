# Proposed unified-spec update: additive yaw fallback

## Push feedback step and configuration

`push_yaw_feedback_additive_fallback_enabled=False` is a boolean, default-off one-shot planning fallback. It is reachable only inside already enabled yaw feedback and its existing `push_yaw_feedback_scope` (including `placement`); it does not expand that scope. When the original quintic suffix is accepted, it remains unchanged. When a nonzero original yaw correction has produced an IK endpoint but its original quintic suffix is rejected during planning, the option permits exactly one additive suffix with the SAME correction and endpoint: the original remaining curve plus a quintic joint displacement with zero initial position/velocity/acceleration and terminal displacement/zero velocity/zero acceleration. No amplitude, Z, endpoint, or timing search occurs. Zero correction and unavailable IK endpoint do not attempt the fallback.

The original movement frame count, feedback boundary, remaining duration, final verification reserve, and action deadline remain unchanged. Example diagnostic: 58 movement frames (2.9 s at 20 Hz) plus 0.1 s verification = 3.0 s counted push. Planning wall time is separately recorded and does not advance or extend physical simulation time. Release, retreat, and unloaded tuck retain their existing separate timing rules and are not described as part of a 3-second whole operation.

## Certificate and rejection semantics

Initially only `BlendedJointPath` is supported. Unsupported path types reject the additive candidate and preserve the original already validated suffix. Each remaining PPoly segment and additive quintic are expressed in the same local polynomial variable. Exact rational arithmetic on stored IEEE coefficients produces combined derivative Bernstein coefficients; de Casteljau interval subdivision certifies velocity/acceleration/jerk against original limits, with maximum depth 18 and a shared hard budget of 8192 subdivision nodes per constructor; exhaustion raises a planning rejection. An unresolved or over-limit certificate is rejection, not a sampled claim. Joint position uses a conservative Bernstein hull. A `1e-10 * (1 + original-term coefficient L1 norm + correction-term coefficient L1 norm)` floating evaluation reserve and outward-rounded float endpoints are included. Existing joint margins, path/collision/camera checks, retained-hand normal band, inverse-dynamics audit, and all runtime physical guards still apply. Actual physical execution faults propagate and never trigger this planning fallback. If either certificate or any additive planning guard rejects, execution continues along the original validated suffix.

## Audit/state dictionary

`push_yaw_feedback_additive_fallback`: `original_quintic_rejection`, `accepted`, `rejection`, `planning_wall_s`; when constructed also `certificate` (method, piece/node counts, max depth, largest floating reserve, no-grid indicator), `boundary_errors`, `terminal_errors`, `limit_ratios`. The existing `push_yaw_feedback_suffix` includes `additive_fallback` with the same audit; accepted fallback sets `selected_reference='additive'`. Existing `fallback_original_suffix` continues to report whether both correction candidates were rejected. Additive planning is not a new physical action/state and consumes no extra simulation frames.
