# 悬空单臂接力放置：只读可行性审计

## 判断

不建议立即把“悬空时松开一手，再靠另一手搬运/重抓”并入生产控制。它可能从双臂末端 IK 过约束中释放一个自由度，但目前没有任何单臂悬空承重或抗翻转的物理 Episode 证据。现有 `holding` 模式要求双侧接触，`retained_contact` 模式要求真实桌面支撑；直接改标志会留下守卫空窗。应先做隔离的短时动力学试验，并以 **实际力、转动、垂直位移、碰撞** 而不是 IK 通过率决定是否继续。此前的支撑锚点方案另见 `V45_SUPPORTED_HANDOFF_DESIGN_AUDIT.md`，其风险较低；此文专门讨论找不到可达双臂支撑锚点时的悬空备选。

## 实证几何与负载

v36 固定 400 场景终末失败有 130 个 `coupled_ik_unreachable`，全部是 `place` 物理步数为零；放宽双臂规划的 v37–v44 试验尚未证明这批病例能够完整成功。case 15 的 v36 终末原始记录 `runs/control_deploy_20260930/v36_case15_trace_snapshot.h5` 最后帧为 26.4 s、`TRANSPORT_TRAY`、目标托盘 0、桌面接触 0，双手力 13.09/12.56 N。托盘中心约 (0.86313, 0.63890, 0.97857) m，底部 z=0.97253 m，目标桌面高 0.8 m，底部净空 172.53 mm。左右 TCP 约 (0.84223, 0.91373, 1.06714) 与 (0.85165, 0.37072, 1.05912) m，相距 543 mm，各离中心约 270 mm。冻结 v36 场景模型中托盘 0 质量 1.2 kg。若只留任一边缘手，重力对该侧抓点的标称力矩量级约 `1.2*9.81*0.27=3.18 N·m`；具体腕力矩和接触摩擦取决于真实接触分布，不能仅凭手部汇总接触力约 13 N 宣称可以悬空稳持。托盘接触几何的摩擦系数为 0.8，但单个汇总的 `gripper_contact_force` 也不能证明抗扭矩容量。

## 若要试验，必须显式增加的控制状态

入口只在 `Machine.carry_place()` 的原完整双臂放置规划零物理运动 IK 失败、到达后站位及真实支撑锚点均无可用路径时；仅限 `completion_first`、本次操作一次、真实双侧力均 >0.5 N、当前 `holding=tray`、无 `retained_contact`、目标仍悬空。原始失败及物理状态保留作对照。预检须在独立副本完成所有手的移动参考、扫掠碰撞、腕相机、关节/速度/功率/期限检查；不得把一次终点 IK 当成接力路径。

建议使用独立的 `AIRBORNE_ONE_HAND_TEST` 内部状态，不把它伪装成 `retained_contact`：

1. `bilateral_hold`: 两手继续闭合，由当前实测 grasp 关系确定托盘和 TCP 的相对位姿。分别预检保留左、保留右的候选。先决定**释放侧整段撤离路径**和另一侧从新姿态到目标的整段参考；若计划是重新抓取，还要检查空手的新夹边预抓、闭合及回到双侧夹持的整段路线。
2. `load_transfer_probe`: 在真机理步中缓慢卸载拟释放手，同时另一手闭合。只有释放手实际力递减、保留手持续受力、托盘姿态和高度稳定，才可进入下一状态。这里可以作为隔离诊断预演，首次不应进入大规模生产 Episode。
3. `airborne_one_hand`: 必须由新的每 2 ms 守卫监控。保留手真实接触力持续 >0.5 N 且闭合，另一手开口并确认真实力 ≤0.5 N，托盘 `support_contact=0`，底部与桌面有安全净空；不得沿用 `Runtime.check_retained_contact()` 的 150/300 ms 桌面微弹跳宽限。连续检查托盘质心高度/速度、倾角与角速度、实际接触点、其他托盘不得被带起，原有非法碰撞、穿透、地面、相机、功率及速度守卫仍启用。任一异常立即走**有真实支撑的受控恢复**，没有支撑可达时终止 attempt，不能直接松手或复位物体。
4. `bilateral_rejoin`：在空手实际避开托盘的前提下，从新的非对称夹边接近并闭合，双侧真实力连续 >0.5 N、相对 grasp 关系稳定后才重新设置 `holding` 并调用真实夹持记录。然后重新规划原放置；或者单臂已把托盘移到可安全落桌的位置时，必须先获得真实桌面承重，再走受支撑的释放流程。最终仍须真实双手释放、一秒稳定和现有 `verify_operation()` 通过。

`Runtime.guard()` 的 `holding` 双侧力丢失 0.12 s 规则不能被静默关掉；新状态必须有更明确的单臂守卫和总时限。原 `retained_contact` 要求 `table_contact>0`，不能用于悬空接力。既有 `Machine.place_push_handoff()` 在实际触桌之后才能切到单臂，且 v39 free-first 物理试验 0/8，四次执行的自由手重新碰盘并使桌面支撑丢失；悬空分支风险至少同等，需要独立验证。

## 可测量的准入试验

先用 case 15 原始终末物理状态进行**只读来源的私有克隆**，不改原 attempt。对左右手分别执行最多 0.25 s 的渐进卸载试验，20 Hz 记录并在 2 ms 子步守卫：保留手力、释放手力、托盘质心高度和竖向速度、倾角/角速度、手指与托盘接触对、腕相机、周围碰撞、穿透及其它托盘高度。建议诊断阈值是相对试验起点下降 <5 mm、倾角始终 ≤5°、释放力 ≤0.5 N 且保留力 >0.5 N 连续 0.15 s；它们只是进一步研究的筛查阈值，不能替代完整任务成功判据。必要时从 `mj_contactForce` 和 contact geom 计算每个手指的切向/法向力及托盘重力矩平衡；汇总 gripper 力不足以证明抗旋转稳定。若两侧均在试验期下沉、翻转或二次接触，则判该案例不适用，继续寻求支撑锚点或更早的双臂重定位。

即便短时承重通过，仍须证明新单臂 TCP 路径和自由手重抓路径在**同一真实夹持状态**下可执行，再做新的完整物理 Episode。优先用 case 15（当前悬空且无到达站位候选）做负载门槛、case 42 做接触失效哨兵、case 4 做原成功不触发回归。不能从 130 个双臂 IK 失败推断 130 个可由单臂救回，也不能把此只读审计计入 400 场景成功率。
