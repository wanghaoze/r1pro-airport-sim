# 带载放置失败后的真实支撑交接：只读设计审计

## 结论与边界

v36 完整 400 场景中有 130 个终末失败属于带载 `place` 双臂 IK（最终目标 73、临时落点 57；来源 `docs/ROBUSTNESS_20260929.md`）。v38 富集组的 15/18/23/27/30/50/155 在 `place` 规划失败时均尚未执行该原语的物理运动，原路径与私有 0.12 rad 路径都拒绝。仅把状态标成“单臂”无法绕过这个事实：托盘仍悬空，`Runtime.guard()` 的双臂夹持要求与 `check_retained_contact()` 的真实桌面支撑要求之间没有无物理接触的合法交接。

可尝试的最小物理策略是：保留原完整放置规划优先级；仅在其零运动 IK 拒绝且到达基座重筛也无合格项后，寻找较近的、**整个托盘足印处于目标桌面内**的支撑锚点。双手实际运送并下降到该点，连续观察桌面承重后才逐步释放难以到位的手。若锚点本身已经满足当前 completion 位置/角度和邻盘间隙验收，双手实际释放并完成原 `verify_operation()`，无须额外推动。其余锚点只有在单手支持推送的全程桌面足印、邻盘间隙和单臂参考都通过预检时才进入交接；否则保持原失败。这个想法尚无新 Episode 证据。

## 状态机入口与候选枚举

入口放在 `Machine.carry_place()` 对固定原语 `place()` 的失败处理之后、抛回原始 `coupled_ik_unreachable` 之前。必须复用 `arrival_replanning.zero_motion_place_failure()` 的步数、物理时间和原语记录检查，限制 completion 模式、仍双手持物、`retained_contact is None`、候选每托盘至多一次。若到达基座重筛确实选择了基座，应先让原逻辑完成该基座的导航与原放置；只有它再次零运动拒绝才考虑锚点。规划失败后要从实际物理观测重建 grasp 关系，不沿用可能被私有 IK 探针改写的命令参考。该分支应是默认关闭的、独立记录的候选。

候选按目标桌坐标系固定顺序枚举：原目标先前已失败，不重复；在目标周围沿桌面长/宽轴取 0、±2、±4 cm 的有限偏移，优先选靠当前实际托盘投影最近且仍距离目标≤3 cm 的点，为最终 5 cm 验收留控制余量。候选保持原目标 yaw 与桌面高度，不修改原 goal 或场景。逐项要求同一目标桌面、`footprint_supported` 的完整足印及安全内缩、其他托盘无遮挡且不误动、可实测的下降接触面；对末态候选还要按原 `slot_geometry_ready`/预约布局检查邻盘间隙。若无需一步到位，第二层候选可以扩到现有 `push_max_distance_m`，但要以候选为起点调用现有 `push_possible` 审核全程足印、转角和邻盘，并对单臂参考与空闲臂撤离做独立预检。当前 `push_possible()` **不允许仅一侧搭在桌边、其余足印悬空**的支撑点启动推送。因此“单角触桌即松手并调用原 push”在现有系统中不可执行。

对每个候选，在隔离的当前物理状态副本中先尝试短距离带载对齐与下降。这里应复用 `continue_loaded_reference`、`object_points`、`touchdown_position`、`plan` 和释放规划的完整检查；必要时将对齐/下降分为显式两个原语，各自遵守配置的 5 s 物理预算，另报导航与规划排除项。必须整段预检双 TCP 位置/朝向、15 mm/0.10 rad 刚性抓持、分支、关节/加速度、腕相机、机器人与三托盘及桌面碰撞；还要确认预期托盘扫掠不会先碰其他盘。候选终点 IK 合格并不足够。所有候选拒绝时返回原始失败码，不能执行半段下降或把私人规划计为成功。

## 真实支撑与控制权转移

`place()` 现有顺序是 `PLACE_TRAY.descend` → 实际 `table_contact` → `PLACE_TRAY.support_contact` → `holding=None` / 可能 `retained_contact=(tray,keep)` → 开爪 → 真实释放验收。可复用这个切换点，但目前 `support_frames>=1` 对边缘接触太弱。建议新分支在切换前连续至少 0.2 s 测量：目标桌面接触未断、桌面法向力高于接触噪声、托盘底接近桌高、倾角≤5°、速度已受控、无非目标托盘抬起/新增穿透。法向力需从 MuJoCo `mj_contactForce` 和接触 geom 分类读取；当前 `table_contact` 只有数量，不能证明桌子真的承重。开爪过程中再逐帧确认桌面承重随自由手卸载而增加且托盘无持续上升、倾倒或支撑断开；不要在两手尚承重时硬性要求桌面独自承担大半重量。完整足印几何只是预检，仍需实际受力转移门槛。

确认支撑后，选保留接触侧时要验证该侧夹爪仍闭合且力>现有阈值，另一侧有整段可验证的开爪与避让路径。切换 `r.holding=None`、`r.grasp_rel=None`、`r.retained_contact=(tray,keep)` 必须与实际释放参考在同一个受监测交接中完成；`Runtime.check_retained_contact()` 随每个物理 tick 继续要求真实桌面接触、保留侧受力和闭爪，原碰撞、相机、关节速度、功率和穿透守卫照常运行。还应补上 `holding` 模式切走后会停止的“其他托盘被带起”和托盘过度倾斜检查，避免交接阶段产生守卫空窗。只有释放侧实际力≤0.5 N 连续两帧，才可进入单臂调整。最终仍需两手都≤0.5 N、桌面支撑和 `verify_operation()`/一秒稳定验收；不得以中途触桌冒充完整任务。

若锚点已在现有 completion 目标容差内，优先**两手实际释放**并检查最终稳定。若仍需移动，保留手推动只适用于原 `push_possible` 的完整桌面扫掠，且必须先确认自由手已真实脱离目标盘并有可执行退避路线。v39 的 8 场景 free-first 实验 0/8 成功，其中四次已执行的自由手仍真实再接触并带起托盘；因此不能把当前单手推进视作已解决的后半程。

## 最小代表案例和风险

- **15**：v38 最后尝试在 frame 529 的 `place` 规划零运动失败，到达基座重筛 0/18 合格，是锚点可达性筛选的首选案例。v36 a002 末帧的真实托盘中心 XY=(0.86313, 0.63890)、底部 z=0.972532 m，目标 XY=(0.85, 0.38)、桌面 z=0.8 m；底部仍悬空约172.5 mm、横向差约259 mm，桌面接触0，双手实测力13.09/12.56 N。当前姿态既不能直接放手，也不能原地落桌后直接用最大18 cm的现有推送到目标。必须先找到物理可达的双手带载中间支撑锚点，或宣告该案例不适用。读数来源：`runs/control_deploy_20260930/v36_case15_trace_snapshot.h5` 和原始v36终末轨迹。
- **42**：v37 富集组已越过一部分 IK 门槛，后续发生真实 `retained_contact_lost`。可用来专门验证支撑转移不会在松手/推送阶段把真实掉桌误报成功。
- **4**：现有完整成功的回归哨兵。新分支仅在原完整规划零运动拒绝后触发，它应继续走完全相同原参考与结果。

主要风险是所有几何锚点仍可能双臂不可达；桌边接触点数量、托盘 COM 与法向承重可能不足以让单手释放；支撑转换后的空闲手可能再次勾住盘；稳定锚点也可能挡住未来托盘；新增对齐/下降与单臂推进会增加真实动作与墙钟。原始 130 个失败并不等于 130 个可修复案例。应先只读筛选候选数，再做隔离规划与核心测试，最后在新运行目录进行少量完整物理 Episode。未满足这些门槛前不应推入 400 场景或预估成功率。
