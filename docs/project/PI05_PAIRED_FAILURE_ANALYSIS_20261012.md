## 从图和数组能确认的现象

1. **误差集中而非所有关节都失效。** 图中零起始通道`right_arm_4`、`right_arm_6`占纯真机/混合全部14关节平方误差的45.75%/47.46%。[episode015叠加图](../../runs/pi05_real_mixed_comparison_20261012_v1/comparison/episode_015_joints.png)的右臂快速变化附近存在明显偏离；仅凭曲线不能区分预测延迟、感知时序误差与多解平均，更不能假定角度绕回错误。这些是动作预测误差，不是实机servo跟踪误差。

2. **未来动作比下一步难，不能混用两种图。** 只读服务器原NPZ复算：下一步双臂RMSE纯真机2.639°、混合2.483°；预测0.20秒处3.510°/3.364°；0.95秒处6.459°/6.343°。下一步夹爪11.501/9.391mm，到0.95秒22.840/22.997mm。前5步聚合为双臂3.068°/2.916°、夹爪15.014/13.351mm。现有闭环每5帧重推理，执行约0.25秒，并非整段1秒不反馈。预测时距曲线：[图](../../runs/pi05_real_mixed_comparison_20261012_v1/comparison/horizon_rmse.png)。

3. **Place开合事件值得优先诊断。** Place总体夹爪RMSE约29mm，明显大于Pick；[episode007第一步图](../../runs/pi05_real_mixed_comparison_20261012_v1/comparison/episode_007_joints.png)仍能跟随主要开合，但切换附近有延迟与短促尖峰。开度从近0跳至约100mm，使少量错时显著增加MSE；29mm不意味着每帧都偏29mm。还需量化松手相对桌面接触的时差，才能判断提前释放、迟释放各占多少。没有证据支持千倍单位错误或左右通道交换。

## 为什么离线趋势尚可，旧仿真闭环仍失败

[闭环实际报告](../../runs/pi05_real_mixed_closed_loop_20261012_v1_reference/comparison_summary.json)中，两模型均Pick0/10、Place0/10；这是固定10场景的独立动作仿真测试，不是真机成功率，也不是完整三动作成功率。Pick未形成稳定相对长边夹持抬升；纯真机Place未满足目标支撑/释放/对齐，混合Place9例记录托盘触地、1例未满足放置门。所有40例执行完成，无教师/IK回退；失败原因字段描述现象，不自动给出根因。

**优先级最高：已确认的机器人和任务表达差异。** 新[real2sim源审计和实测](REAL2SIM.md)表明原数据含4个腰关节，旧19维接口只保留双臂/夹爪并增加base3，旧仿真腰部固定。旧右肘下限−1.7453rad，而所选源URDF为−2.0944rad，真机示范反馈出现约−2.069rad。相同臂关节角在不同腰姿态下不对应相同末端世界位姿；超旧限位的目标也不能按原示范实现。这是确认的不一致，尚未完成消融证明其失败贡献。所选URDF与实机完整硬件身份、驱动参数仍需核对。

此外真机来源底盘目标为零，旧仿真Place包含目标桌语义，不能认为静止底盘真机放置示范天然涵盖桌间移动。桌/盘/相机世界配准尚无已验证实测依据。新real2sim两例原命令回放流程已闭合，但未完成真实物体配准，不能称已经修复抓放或证明任务成功。

**其次：BC在偏离示范后的恢复能力未经训练证明。** 104图每一步重新获得正确的录制观测；闭环一旦夹空、托盘滑落或双臂不同步，下一帧图像和状态就变化。离线误差较小不保证此时能恢复。这与[DAgger原论文](https://proceedings.mlr.press/v15/ross11a.html)指出的策略诱导观测分布变化一致，但本项目尚无定量消融，不能称它是唯一根因或已执行DAgger。

**视觉差异存在，但亮度不是已证实的主因。** [既有数据审计](REAL_ONLY_PI05_20261012.md)抽样头图real均值124/255、sim91.7/255，同时还混有内容、视角与遮挡差异。真机train/test头亮度124/123.3接近；val配对亮度0.7/1/1.3倍的关节MSE相对原图约−2%/0/+2%。这不支持“只调亮即可解决”；也不排除相机外参、局部遮挡和渲染域差异。

**归一化未查到确定错误。** 各checkpoint归一化身份、训练来源及rad/m语义已核。test约7.88%的第0关节目标超train的q01/q99，只说明尾部覆盖，不等于非法或已裁剪。应继续查反归一化往返和执行器饱和，而非直接更换norm；[OpenPI官方说明](https://github.com/Physical-Intelligence/openpi/blob/main/docs/norm_stats.md)也是训练/推理统计一致性的依据。

## 推荐改进顺序（建议，未自动实施）

1. **先完成执行一致性验收，再增加训练。** 沿独立real2sim路线核硬件关节、腰姿态、夹爪总开口、执行器范围、桌盘配准与相机外参。用原真机命令做独立物理回放，分报关节跟踪与真实托盘接触结果；此回放不作为VLA回退，也不改旧测试标签。明确选择是否将腰纳入策略动作/状态，或限定合法固定腰数据；这是训练动作空间取舍，需用户决定。
2. **对关键事件补数据和指标。** 单列右臂4/6快速变化、双臂闭合同步、触桌前后与释放窗口；报告事件时间误差、局部RMSE及物体接触结果。训练集增加真实纠偏、抓偏和释放过渡的覆盖，而非重复静止帧凑数量。数据身份按录制/场景隔离，任何采样或损失加权先用val验证。
3. **小规模验证反馈频率。** 在相同val初态对每次执行1、2、5帧做纯模型闭环消融，记录成功率、推理延迟和抖动；不假定更频繁一定更好。保持同checkpoint、噪声及物理条件，不能凭0.95秒预测误差断言当前执行整秒。
4. **最后再比较训练策略。** 同一父模型初始化、相同更新预算和评测条件比较纯真机/混合，报告多随机种子与episode级不确定性。当前模型初始化不同，不能归因于比例本身。[π0.5论文](https://arxiv.org/abs/2504.16054)强调异构数据共同训练与泛化；它不证明当前少量同场景微调能自动解决机器人/相机不一致。
5. 若执行一致性已通过而模型仍在偏离后失效，再考虑DAgger类失败状态标注与追加训练。教师只能明确用于生成训练标签，最终测试全程模型执行。保持独立最终留出集；此次19条已用于诊断，不应反复调参后仍将它们当未见最终测试证据。

推荐先做第1项。当前证据不支持直接归咎亮度、归一化或π0.5架构，也不支持仅延长训练就能修复。需要变更训练方案或动作空间时另行取得用户决策。
